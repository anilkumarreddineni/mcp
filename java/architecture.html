Order Assistant Architecture

A chat UI where Claude answers order questions. Claude never reads order data directly. It asks mcp-client to call MCP tools, and mcp-server turns those calls into REST requests to order-service.

One question, end to end

What happens when someone asks “What's the status of order 1003?”

  1. Browser → mcp-clientThe Angular chat-ui posts the message to /api/chat. The browser session id becomes the conversation id.
  2. Memory advisorEarlier turns of this conversation are added, so follow-ups such as “and 1004?” make sense.
  3. mcp-client → ClaudeThe system prompt, history, question and the two tool definitions from mcp-server go to the Messages API.
  4. Claude → mcp-clientClaude replies with a tool call: getOrderStatus {"orderId":"1003"}.
  5. Tool calling advisor → mcp-serverThe MCP client calls the tool on /mcp.
  6. mcp-server → order-serviceGET /orders/1003/status returns SHIPPED, which goes back as the tool result.
  7. mcp-client → ClaudeA second request carries the tool result. Claude answers “Order 1003 has been shipped.”
  8. mcp-client → BrowserThe reply is shown and the turn is saved to the conversation's memory.

Services

ServicePortJob
mcp-client8082Talks to Claude and acts as the MCP client. The Angular chat-ui (port 4200) is its front end and proxies /api to it.
mcp-server8080Exposes order lookups as MCP tools. Also answers GET /hello.
order-service8081Holds order statuses: PENDING, PROCESSING, SHIPPED, DELIVERED, CANCELLED.

When something is down

  • mcp-client starts even if mcp-server is down. It connects on the first chat message.
  • If mcp-server or the Claude API can't be reached, the user gets a friendly “try again” reply (HTTP 503) and the details go to the mcp-client log.
  • An unknown order ID or an unreachable order-service comes back to Claude as a tool error, so Claude can say the order doesn't exist.
  • start-all.bat starts order-service, then mcp-server, then mcp-client, and waits for each to answer before starting the next.
  • Each service writes logs/<service>.log, rotated at 10 MB and kept for 7 days.
