How Claude Sees Tools

Claude never connects to mcp-server. mcp-client sends Claude a description of each tool with every request, Claude asks for a tool by name, and mcp-client runs it. One order question takes two requests to Claude.

Where a tool's definition comes from

  1. mcp-server · OrderTools.java@McpTool gives the name and description. @McpToolParam and the method's parameters give the input schema.
  2. mcp-server · /mcpAnswers the MCP tools/list request with those definitions.
  3. mcp-client · ChatClientConfigWraps each one as a ToolCallback. .defaultTools(mcpTools) attaches them to every chat.
  4. Messages API requestThey go in the "tools" field next to the messages, on every call.

Remember

  • Claude never runs a tool.It replies with a tool_use request. mcp-client runs the tool through mcp-server.
  • Claude remembers nothing between calls.Every request resends the system prompt, the history and the tools.
  • A question that needs a tool takes two requests.The first gets the tool_use. The second carries the result and gets the answer.
  • Descriptions steer tool choice.Claude picks a tool only from its name, description and schema, so write them for Claude.
  • Chat memory keeps reply text only.Earlier tool calls and results are not in the history of the next question.
  • SYSTEM and TOOL are Spring AI's labels.The API has only user and assistant roles, plus a separate system field.
  • Add a tool without touching mcp-client.A new @McpTool method shows up the next time mcp-client connects.
  • See it in the log.mcp-client/logs/mcp-client.log prints each request's messages and its tools (2) list.
